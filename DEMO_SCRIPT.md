# DomainForge AI — Judge Demo Script (~3 minutes)

**One line:** *A no-code platform that helps non-technical domain experts turn a plain-language
problem into a working, testable, publishable AI agent.*
**Theme:** Accessibility & Social Good.

> Keep in mind: everything runs in **Demo mode** (deterministic built-in tools, clearly-labelled
> synthetic sample data). Do not claim real-world impact or professional certification.

---

### 0. The problem (20s)
"Powerful AI tools exist, but the people closest to real community problems — a civil engineer
looking at street flooding, a community group documenting accessibility barriers — usually can't
build the tooling themselves. DomainForge lowers that barrier: describe the problem in ordinary
language, and we help you build the agent."

### 1. Dashboard & theme (20s)
- Open the app. Point out the tagline, **Demo mode** badge, and the "How this fits the theme" cards
  (lower the knowledge barrier · inclusive by design · built for community good).
- Mention accessibility is built in: try pressing **Tab** — focus rings are clearly visible; toggle
  light/dark with the theme button.

### 2. Create an agent from a prompt (40s)
- Click **Try the guided demo** (prefills the Urban Waterlogging example) *or* **Create an agent**.
- Walk through the 3 plain-language steps (problem → data → outcome). Note the help text and the
  "Insert example" shortcuts.
- Click **Review & generate** → **Generate my agent**. The Master Agent drafts a full proposal:
  name, purpose, beneficiaries, an ordered plain-language workflow, suggested tools, checks, and
  limitations. Edit a step title to show it's fully editable, then **Save agent**.

### 3. Run it for real (40s)
- In the workspace, open the **Run** tab. Keep **Use sample dataset** on (8 synthetic storm records).
- Click **Run agent**. Watch the five tools execute step by step with live status and logs.
- Open **Results**: a structured report (what the data shows, key observations, evidence gaps,
  next steps), the inputs that informed it, assumptions, a quality checklist, and limitations.

### 4. Improve it (25s)
- Open **Improve**. Click the suggestion *"Show which data supports each conclusion"* → **Save as
  new version**. Show the before/after: the workflow gains a step and a new version (v2) is logged
  in the version history.

### 5. Publish & share (40s)
- Open **Deploy**. Show the **Draft → Test → Publish** states and the pre-publish checklist
  (all green after our test run). Click **Publish agent page**.
- A stable URL appears (`/a/urban-waterlogging-analysis-agent`). Click **Open public page**.
- On the public page, a visitor can run the agent — no editing controls. Run it to prove it works.

### 6. Unpublish (15s)
- Back in **Deploy**, click **Unpublish**. Reload the public page → it now clearly says the agent
  isn't available and the public run endpoint returns 403.

### Close (10s)
"Waterlogging and accessibility are just two examples — the same flow works for public health,
agriculture, education, or any domain a community expert cares about. It's a prototype, but it
shows how we can put useful technology in the hands of the people who understand the problem best."
